# Goal 模式 — 目标驱动自主执行

> 版本：v1.0
> 日期：2026-06-24
> 状态：已实现
> 关联：`docs/superpowers/specs/2026-06-22-session-compression.md`（上下文压缩，goal 模式长循环依赖压缩）

---

## 0. 背景

普通 task 模式中，Agent 遇到危险命令会弹窗阻塞等待用户确认，打断自主执行流。用户希望能设定一个明确目标，让 Agent 自主持续工作直到目标达成，中途不打断。

Goal 模式是 task 模式的增强：设定目标后，Agent 获得更大的自主权（跳过普通危险命令确认），并通过 `finish_goal` 工具显式声明目标达成。

---

## 1. 设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 作用范围 | 仅 task 模式 | goal 是 task 的增强，chat/knowledge 不受影响 |
| 权限策略 | 跳过普通危险命令确认，仅保留极危险命令确认 | 平衡自主性与安全性；rm -rf /、sudo 等灾难性命令仍需人工确认 |
| 完成判定 | 新增 `finish_goal` 工具 | agent 显式调用表示目标达成，附完成总结；比"无 tool_call 即完成"更精确 |
| 分叉继承 | 继承 Goal | 与 Mode/KnowledgeBaseID 一致 |

---

## 2. 数据模型变更

Conversation 表新增字段：
```go
Goal string `gorm:"type:text;default:''" json:"goal"`  // task 模式目标（空=普通 task）
```

- AutoMigrate 自动加列
- 空 = 普通 task 模式（行为不变）；非空 = goal 模式

## 3. 核心机制

### 3.1 Goal 注入 System Prompt

`react_agent.go` 的 `taskSystemPrompt` 在 goal 非空时注入目标驱动指令：

```
### 目标驱动模式（已开启）
- 你正在为一个明确的目标工作，请持续执行直到目标完全达成：
  > {goal}
- 当且仅当你确认目标已完全达成，调用 finish_goal 工具结束任务
- 不要在目标未达成时提前停下来问用户——遇到障碍尝试不同方案自行解决
- 目标确实无法达成时，调用 finish_goal 并将 success 设为 false
- 普通命令无需用户确认即可执行，但极危险命令仍需确认
```

### 3.2 finish_goal 工具

`internal/eino/finish_goal_tool.go`：

- **工具名**：`finish_goal`
- **参数**：`summary`（必填，成果总结）、`success`（可选，默认 true）
- **行为**：标记 `finished=true`，存储 summary/success
- **检测**：`react_agent.go` 事件循环中，Tool result 阶段检测 `toolName == "finish_goal"` → `runCancel()` 结束循环
- **结束分类**：新增"情况 0"——`goalFinished` 时发 notice（"✅ 目标已达成" 或 "⚠️ 目标未达成" + summary）+ done

### 3.3 BashTool 权限策略

`internal/eino/bash_tool.go` 新增 `autoApprove` 字段和 `criticalBashPatterns` 硬编码列表：

| 模式 | autoApprove | 普通危险命令（黑名单） | 极危险命令（criticalBashPatterns） |
|------|-------------|----------------------|-----------------------------------|
| 普通 task | false | 弹窗确认 | 弹窗确认 |
| goal 模式 | true | **自动放行** | 弹窗确认 |

极危险命令列表（硬编码，不可配置，始终确认）：
- `rm -rf /`、`rm -rf ~`、`sudo`、`mkfs`、`dd if=`、`chmod 777 /`、`:(){ :|:& };:`

## 4. 调用链

```
前端 InputArea.vue
  ├─ 设 goal → SetGoal(convID, goal) → 持久化到 Conversation.Goal
  └─ 发送任务 → StreamTask({ ..., goal: goal.value })
       └─ task.go StreamTask
            ├─ BuildTaskTools(ctx, workDir, emitter, planEnabled, req.Goal)
            │    ├─ goal != "" → NewBashTool(autoApprove=true) + NewFinishGoalTool()
            │    └─ goal == "" → NewBashTool(autoApprove=false), finishGoalTool=nil
            └─ RunTaskAgent(ctx, llm, tools, bashTool, workDir, history, userMsg, userInput, planEnabled, req.Goal, finishGoalTool)
                 ├─ taskSystemPrompt(workDir, planEnabled, goal) → 注入目标指令
                 └─ 事件循环:
                      ├─ Tool result: toolName=="finish_goal" → goalFinished=true → runCancel()
                      └─ 结束分类: goalFinished → notice("✅ 目标已达成" + summary) → done
```

## 6. 额外修复：BashConfirmDialog 事件名 BUG

探索发现 `BashConfirmDialog.vue` 监听 `task:bash_confirm` 事件，但后端从未 emit 该事件名（实际 emit 的是 `task:step`，type 字段为 `bash_confirm`）。导致弹窗从未显示，BashTool 总是 120s 超时。

修复：改为监听 `task:step` 并在 `payload.type === 'bash_confirm'` 时显示弹窗。

## 7. 技术约束

- **非 goal 的 task 模式行为不变**：autoApprove=false，无 finish_goal 工具
- **chat/knowledge 模式不受影响**：goal 字段为空，不注入 system prompt
- **极危险命令始终确认**：硬编码列表，不受 autoApprove 影响
- **压缩中间件自动生效**：goal 模式长循环更需要上下文压缩，reduction + summarization 自动挂载
- **死循环检测仍有效**：6 次相同工具签名仍会中断，防止 goal 模式陷入无限循环
- **MaxIterations=100 仍为天花板**：goal 模式不会因步数限制提前结束（100 步足够），正常由 finish_goal 结束
